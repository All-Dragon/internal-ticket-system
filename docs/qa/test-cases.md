# Ручные тест-кейсы Internal Ticket System

## Общие условия

- Приложение запущено и доступно в браузере.
- API и база данных доступны.
- Если в кейсе не указано обратное, пользователь не авторизован как администратор.
- Валидные учётные данные администратора задаются переменными окружения.
- Каждый кейс выполняется на независимых тестовых данных.

## AUTH-001 — Успешный вход и выход администратора

**Приоритет:** Critical

**Предусловия:** пользователь не авторизован.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть главную страницу | Отображается форма входа администратора |
| 2 | Ввести валидный логин и пароль | Значения отображаются в соответствующих полях; пароль маскируется |
| 3 | Нажать «Войти» | Вход выполнен; отображается состояние авторизованного администратора |
| 4 | Проверить доступные действия незавершённой заявки | Администратору доступно удаление заявки |
| 5 | Нажать «Выйти» | Сессия завершена; снова отображается форма входа |
| 6 | Обновить страницу | Пользователь остаётся неавторизованным |

## AUTH-002 — Отказ во входе с невалидными данными

**Приоритет:** High

**Предусловия:** пользователь не авторизован.

### Тестовые данные

| Вариант | Логин | Пароль | Ожидаемая ошибка |
|---|---|---|---|
| 1 | Пусто | Пусто | Требование ввести логин и пароль |
| 2 | Валидный | Неверный | Ошибка аутентификации |
| 3 | Несуществующий | Произвольный | Ошибка аутентификации без раскрытия существования пользователя |

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть главную страницу | Отображается форма входа |
| 2 | Ввести данные выбранного варианта | Поля принимают введённые значения |
| 3 | Нажать «Войти» | Отображается соответствующее сообщение об ошибке |
| 4 | Проверить состояние пользователя | Администраторская сессия не создана; защищённые действия недоступны |
| 5 | Закрыть сообщение об ошибке | Сообщение исчезает; форма остаётся доступной |

## TICKET-001 — Создание заявки с валидными данными

**Приоритет:** Critical

**Тестовые данные:** заголовок `Не работает принтер`, описание `Принтер не печатает документы`, приоритет `High`.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть главную страницу | Отображается форма создания заявки |
| 2 | Заполнить заголовок, описание и приоритет | Значения отображаются в соответствующих полях |
| 3 | Нажать кнопку создания | Заявка успешно создана; открывается окно с её данными |
| 4 | Проверить данные в окне | Заголовок, описание и приоритет совпадают с введёнными; статус равен `New` |
| 5 | Закрыть окно | Окно закрывается; форма очищается; приоритет возвращается к `Normal` |
| 6 | Найти созданную заявку в таблице | Заявка отображается с корректными данными и уникальным ID |
| 7 | Обновить страницу | Созданная заявка сохраняется и продолжает отображаться |

## TICKET-002 — Валидация полей создания заявки

**Приоритет:** High

### Тестовые данные

| Вариант | Заголовок | Описание | Ожидаемый результат |
|---|---|---|---|
| 1 | Пусто | Пусто | Ошибка обязательного заголовка; заявка не создаётся |
| 2 | 2 символа | Валидное | Ошибка минимальной длины; заявка не создаётся |
| 3 | 3 символа | Валидное | Заявка создаётся |
| 4 | 120 символов | Валидное | Заявка создаётся |
| 5 | 121 символ | Валидное | Ошибка максимальной длины; заявка не создаётся |
| 6 | Валидный | 1000 символов | Заявка создаётся |
| 7 | Валидный | 1001 символ | Ошибка максимальной длины; заявка не создаётся |

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть главную страницу | Форма создания доступна |
| 2 | Ввести данные выбранного варианта | Счётчики и значения полей обновляются |
| 3 | Перевести фокус или отправить форму | Для невалидного поля появляется понятное сообщение |
| 4 | Проверить семантическое состояние поля | Невалидное поле имеет `aria-invalid="true"` и связано с текстом ошибки |
| 5 | Проверить результат отправки | Валидные данные сохраняются; невалидные не создают заявку |

## TICKET-003 — Просмотр подробной информации о заявке

**Приоритет:** High

**Предусловия:** существует заявка с известными заголовком, описанием, статусом и приоритетом.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Найти заявку в таблице | Отображается строка нужной заявки |
| 2 | Нажать «Посмотреть» | Открывается модальное окно выбранной заявки |
| 3 | Проверить данные | ID, заголовок, описание, статус и приоритет соответствуют заявке |
| 4 | Закрыть окно | Окно закрывается; пользователь возвращается к таблице |

## TICKET-004 — Изменение одного поля заявки

**Приоритет:** High

**Предусловия:** существует заявка не в статусе `done`.

### Варианты

- изменить только заголовок;
- изменить только описание;
- изменить только приоритет.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть редактирование заявки | Поля заполнены текущими данными |
| 2 | Изменить одно поле выбранного варианта | Изменённое значение отображается в поле; остальные значения не меняются |
| 3 | Сохранить заявку | Окно закрывается; операция завершается успешно |
| 4 | Проверить строку таблицы | Изменено только выбранное поле |
| 5 | Открыть подробную информацию | Отображаются обновлённые данные |
| 6 | Обновить страницу и повторно открыть заявку | Изменение сохранено в базе; остальные поля остались прежними |

## TICKET-005 — Изменение статуса и терминальное состояние `done`

**Приоритет:** Critical

**Предусловия:** существует заявка в статусе `new`.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Изменить статус на `in_progress` | В таблице отображается `In Progress` |
| 2 | Обновить страницу | Статус `In Progress` сохраняется |
| 3 | Изменить статус на `done` | В таблице отображается `Done` |
| 4 | Проверить поле статуса | Изменение статуса завершённой заявки недоступно |
| 5 | Обновить страницу | Статус `Done` сохраняется и остаётся терминальным |

## TICKET-006 — Запрет редактирования завершённой заявки

**Приоритет:** Critical

**Предусловия:** существует заявка в статусе `done`.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Найти заявку в таблице | Заявка отображается со статусом `Done` |
| 2 | Проверить действие редактирования в таблице | Редактирование недоступно |
| 3 | Открыть подробную информацию | Отображаются данные завершённой заявки |
| 4 | Проверить действие редактирования в окне | Редактирование недоступно; состояние понятно пользователю |
| 5 | Отправить запрос изменения напрямую к API | API отклоняет изменение соответствующим HTTP-статусом и сообщением |

## TICKET-007 — Управление доступом к удалению заявки

**Приоритет:** Critical

### Матрица доступа

| Роль | Статус | Ожидаемый результат |
|---|---|---|
| Пользователь | `new` или `in_progress` | Удаление недоступно |
| Пользователь | `done` | Удаление недоступно |
| Администратор | `new` или `in_progress` | Удаление доступно |
| Администратор | `done` | Удаление недоступно |

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть приложение в требуемой роли | Отображается список заявок |
| 2 | Найти заявку с требуемым статусом | Отображается нужная строка |
| 3 | Проверить удаление из таблицы и окна просмотра | Доступность действия соответствует матрице |
| 4 | Для разрешённого варианта нажать удаление | Открывается окно подтверждения с ID заявки |
| 5 | Подтвердить удаление | Заявка исчезает из таблицы и больше не доступна через API |
| 6 | Для запрещённого варианта отправить DELETE напрямую | API отклоняет запрос; заявка сохраняется |

## SEARCH-001 — Поиск по заголовку и описанию

**Приоритет:** Medium

**Предусловия:** существуют несколько заявок с различающимися заголовками и описаниями.

### Варианты

- полное совпадение в заголовке;
- частичное совпадение в заголовке;
- совпадение только в описании;
- запрос в другом регистре, включая кириллицу;
- запрос без совпадений.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Ввести поисковый запрос | Значение отображается в поле поиска |
| 2 | Дождаться обновления списка | Показаны только заявки с совпадением в заголовке или описании |
| 3 | Проверить неподходящие заявки | Заявки без совпадения отсутствуют |
| 4 | Ввести запрос без совпадений | Таблица скрывается; отображается состояние «Заявки не найдены» |
| 5 | Очистить поиск | Список заявок восстанавливается |

## FILTER-001 — Совместная фильтрация и сортировка

**Приоритет:** Medium

**Предусловия:** существуют заявки разных статусов и приоритетов.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Выбрать статус `Done` | Отображаются только завершённые заявки |
| 2 | Дополнительно выбрать приоритет `High` | Остаются только заявки `Done + High` |
| 3 | Проверить выборку | Заявки, не соответствующие хотя бы одному условию, отсутствуют |
| 4 | Очистить статус и приоритет | Снова отображаются заявки разных приоритетов |
| 5 | Выбрать сортировку по приоритету по возрастанию | Заявки расположены в порядке `Low → Normal → High` |
| 6 | Изменить направление на убывание | Порядок разворачивается |
| 7 | Нажать «Сбросить фильтры» | Фильтры очищаются; сортировка возвращается к дате создания по убыванию |

## PAGINATION-001 — Навигация и изменение размера страницы

**Приоритет:** Medium

**Предусловия:** выборка содержит 6 заявок с общим уникальным поисковым маркером.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Найти подготовленные заявки по маркеру | В выборке ровно 6 заявок |
| 2 | Установить размер страницы 5 | На первой странице отображается 5 заявок; доступна вторая страница |
| 3 | Проверить первую страницу | «Назад» недоступна; «Далее» доступна; показан диапазон 1–5 из 6 |
| 4 | Нажать «Далее» | Открывается вторая страница с одной оставшейся заявкой |
| 5 | Проверить вторую страницу | «Назад» доступна; «Далее» недоступна; показан диапазон 6–6 из 6 |
| 6 | Нажать «Назад» | Пользователь возвращается на первую страницу |
| 7 | Установить размер страницы 10 | Все 6 заявок отображаются на одной странице |

## QUICK-001 — Быстрые фильтры и их сброс

**Приоритет:** Medium

**Предусловия:** существуют заявки всех статусов и приоритетов.

### Варианты быстрых фильтров

- `Новые`;
- `В работе`;
- `Закрытые`;
- `Высокий приоритет`.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Нажать выбранный быстрый фильтр | Кнопка получает `aria-pressed="true"`; остальные быстрые фильтры неактивны |
| 2 | Проверить обычные фильтры | Соответствующее поле статуса или приоритета синхронизировано с быстрым фильтром |
| 3 | Проверить таблицу | Отображаются только подходящие заявки |
| 4 | Нажать «Все заявки» | Быстрый фильтр отключается; обычные фильтры очищаются; заявки снова отображаются |
| 5 | Повторно применить быстрый фильтр | Фильтр снова становится активным |
| 6 | Нажать обычную кнопку «Сбросить фильтры» | Быстрый фильтр отключается; активной становится кнопка «Все заявки» |
