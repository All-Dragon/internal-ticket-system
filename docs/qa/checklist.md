# Checklist ручного тестирования Internal Ticket System

## Обозначения

- `[ ]` — не проверено;
- `[x]` — проверка пройдена;
- результат с дефектом сопровождается ссылкой на баг-репорт.

## 1. Окружение и smoke

- [ ] Главная страница открывается без ошибки.
- [ ] Статические ресурсы frontend загружаются.
- [ ] Health endpoint возвращает успешный ответ.
- [ ] API доступен через настроенный base URL.
- [ ] Миграции применяются при запуске Docker-окружения.
- [ ] Приложение запускается с пустой базой данных.
- [ ] Приложение запускается с существующими данными.
- [ ] Ошибки frontend и API отсутствуют в консоли браузера при основном сценарии.
- [ ] В логах backend отсутствуют необработанные исключения при основном сценарии.

## 2. Авторизация администратора

- [ ] Форма входа отображается неавторизованному пользователю.
- [ ] Поля логина и пароля имеют понятные названия.
- [ ] Пароль скрыт по умолчанию.
- [ ] Кнопка показа пароля изменяет видимость значения.
- [ ] Валидные данные позволяют войти.
- [ ] Пустые поля не позволяют войти.
- [ ] Неверный логин не позволяет войти.
- [ ] Неверный пароль не позволяет войти.
- [ ] Ошибка входа не раскрывает существование пользователя.
- [ ] Сообщение об ошибке можно закрыть.
- [ ] После входа отображается состояние администратора.
- [ ] После выхода защищённые действия становятся недоступны.
- [ ] После выхода обновление страницы не восстанавливает завершённую сессию.
- [ ] Истёкший или невалидный токен обрабатывается без падения страницы.

## 3. Создание заявки

- [ ] Форма создания отображается на главной странице.
- [ ] Заголовок обязателен.
- [ ] Заголовок короче 3 символов отклоняется.
- [ ] Заголовок длиной 3 символа принимается.
- [ ] Заголовок длиной 120 символов принимается.
- [ ] Заголовок длиннее 120 символов отклоняется.
- [ ] Описание можно оставить пустым.
- [ ] Описание длиной 1000 символов принимается.
- [ ] Описание длиннее 1000 символов отклоняется.
- [ ] Доступны приоритеты `Low`, `Normal` и `High`.
- [ ] Приоритет по умолчанию равен `Normal`.
- [ ] Ошибки валидации появляются у соответствующих полей.
- [ ] После исправления значения ошибка исчезает.
- [ ] Невалидная форма не отправляет заявку.
- [ ] Валидная форма создаёт ровно одну заявку.
- [ ] Созданная заявка получает уникальный ID.
- [ ] Начальный статус созданной заявки равен `New`.
- [ ] После создания открывается окно с данными заявки.
- [ ] Окно созданной заявки можно закрыть.
- [ ] После успешного создания форма очищается.
- [ ] После повторной отправки не происходит случайного дублирования заявки.

## 4. Таблица заявок

- [ ] Таблица отображается при наличии заявок.
- [ ] Заголовки столбцов соответствуют содержимому.
- [ ] ID, заголовок, описание, статус и приоритет отображаются в правильных столбцах.
- [ ] Даты создания и обновления отображаются в UTC.
- [ ] Длинный заголовок не ломает ширину таблицы.
- [ ] Длинное описание не ломает ширину таблицы.
- [ ] Полный заголовок доступен пользователю при сокращённом отображении.
- [ ] Полное описание доступно пользователю при сокращённом отображении.
- [ ] Пустое описание отображается понятным текстом.
- [ ] Действия относятся к правильной заявке.
- [ ] Обновление страницы сохраняет данные таблицы.

## 5. Просмотр заявки

- [ ] Кнопка просмотра открывает правильную заявку.
- [ ] Окно имеет доступное имя с ID заявки.
- [ ] В окне корректно отображаются все поля.
- [ ] Приоритет и статус имеют понятные текстовые значения.
- [ ] Окно закрывается кнопкой закрытия.
- [ ] Окно закрывается клавишей `Escape`.
- [ ] После закрытия фокус возвращается на элемент, открывший окно.
- [ ] После редактирования окно просмотра показывает обновлённые данные.

## 6. Изменение статуса

- [ ] Статус `new` можно изменить на `in_progress`.
- [ ] Статус `new` можно изменить на `done`, если это допускается бизнес-логикой.
- [ ] Статус `in_progress` можно изменить на `done`.
- [ ] Изменённый статус сохраняется после перезагрузки.
- [ ] Во время обновления невозможно отправить повторное изменение.
- [ ] Заявка в статусе `done` не возвращается в другой статус.
- [ ] Ошибка API при изменении статуса отображается пользователю.

## 7. Редактирование заявки

- [ ] Редактирование доступно для заявки не в статусе `done`.
- [ ] Открывается окно выбранной заявки.
- [ ] Поля заполнены текущими значениями.
- [ ] Можно изменить только заголовок.
- [ ] Можно изменить только описание.
- [ ] Можно изменить только приоритет.
- [ ] Неизменённые поля сохраняют прежние значения.
- [ ] Для полей действуют те же ограничения, что при создании.
- [ ] Невалидные данные не сохраняются.
- [ ] После сохранения таблица обновляется.
- [ ] После сохранения окно просмотра показывает новые данные.
- [ ] После перезагрузки изменения сохраняются.
- [ ] Отмена или закрытие окна не сохраняет несохранённые изменения.
- [ ] Заявку в статусе `done` нельзя редактировать из таблицы.
- [ ] Заявку в статусе `done` нельзя редактировать из окна просмотра.

## 8. Удаление заявки

- [ ] Неавторизованный пользователь не видит действие удаления в таблице.
- [ ] Неавторизованный пользователь не видит действие удаления в окне просмотра.
- [ ] Прямой DELETE без авторизации отклоняется API.
- [ ] Администратор может начать удаление незавершённой заявки из таблицы.
- [ ] Администратор может начать удаление незавершённой заявки из окна просмотра.
- [ ] Перед удалением отображается окно подтверждения с правильным ID.
- [ ] Отмена закрывает окно и сохраняет заявку.
- [ ] Подтверждение удаляет ровно одну выбранную заявку.
- [ ] Удалённая заявка исчезает из таблицы.
- [ ] Удалённая заявка больше не доступна через API.
- [ ] Заявку в статусе `done` нельзя удалить через UI.
- [ ] Попытка удалить `done` через API отклоняется.
- [ ] Повторное удаление отсутствующей заявки обрабатывается корректно.

## 9. Поиск

- [ ] Поиск находит заявку по полному заголовку.
- [ ] Поиск находит заявку по части заголовка.
- [ ] Поиск находит заявку по описанию.
- [ ] Поиск не зависит от регистра латиницы.
- [ ] Поиск не зависит от регистра кириллицы.
- [ ] Пробелы в начале и конце запроса обрабатываются корректно.
- [ ] Специальные символы не вызывают ошибку приложения.
- [ ] Неподходящие заявки отсутствуют в выдаче.
- [ ] При отсутствии результатов отображается «Заявки не найдены».
- [ ] Очистка поля восстанавливает список.
- [ ] Новый поиск возвращает пользователя на первую страницу.

## 10. Фильтрация

- [ ] Доступна фильтрация по каждому статусу.
- [ ] Доступна фильтрация по каждому приоритету.
- [ ] Значение «Все статусы» снимает фильтр статуса.
- [ ] Значение «Все приоритеты» снимает фильтр приоритета.
- [ ] Статус и приоритет применяются одновременно по правилу `AND`.
- [ ] Поиск работает совместно со статусом и приоритетом.
- [ ] Неподходящие заявки отсутствуют в таблице.
- [ ] Применение фильтра возвращает пользователя на первую страницу.
- [ ] Кнопка сброса очищает поиск, статус и приоритет.

## 11. Сортировка

- [ ] Дата создания сортируется по возрастанию.
- [ ] Дата создания сортируется по убыванию.
- [ ] Приоритет сортируется `Low → Normal → High`.
- [ ] Приоритет сортируется `High → Normal → Low`.
- [ ] Статус сортируется `New → In Progress → Done`.
- [ ] Статус сортируется `Done → In Progress → New`.
- [ ] Сортировка применяется к отфильтрованной выборке.
- [ ] Сброс возвращает сортировку по дате создания по убыванию.

## 12. Быстрые фильтры

- [ ] Кнопка «Новые» показывает только заявки `New`.
- [ ] Кнопка «В работе» показывает только заявки `In Progress`.
- [ ] Кнопка «Закрытые» показывает только заявки `Done`.
- [ ] Кнопка «Высокий приоритет» показывает только заявки `High`.
- [ ] Активная кнопка имеет `aria-pressed="true"`.
- [ ] Остальные быстрые фильтры имеют `aria-pressed="false"`.
- [ ] Быстрый фильтр синхронизируется с обычными фильтрами.
- [ ] Переключение быстрого фильтра корректно обновляет таблицу.
- [ ] Кнопка «Все заявки» отключает быстрый фильтр.
- [ ] Обычная кнопка сброса отключает быстрый фильтр.

## 13. Пагинация

- [ ] Отображается корректный диапазон и общее количество заявок.
- [ ] На первой странице кнопка «Назад» недоступна.
- [ ] На последней странице кнопка «Далее» недоступна.
- [ ] Кнопка «Далее» открывает следующую страницу.
- [ ] Кнопка «Назад» открывает предыдущую страницу.
- [ ] Кнопка с номером открывает выбранную страницу.
- [ ] Активная страница имеет `aria-current="page"`.
- [ ] Доступны размеры страницы 5, 10, 20 и 50.
- [ ] Изменение размера обновляет количество строк.
- [ ] Изменение размера пересчитывает число страниц.
- [ ] Изменение размера возвращает пользователя на первую страницу.
- [ ] Заявки не дублируются между соседними страницами.
- [ ] Заявки не пропускаются при последовательном переходе по страницам.

## 14. Состояния и обработка ошибок

- [ ] Во время первоначальной загрузки отображается состояние загрузки.
- [ ] Состояние загрузки имеет `aria-busy="true"`.
- [ ] Пустая выборка отличается от ошибки загрузки.
- [ ] Ошибка API отображается понятным сообщением.
- [ ] Сообщение об ошибке имеет роль `alert`.
- [ ] Сообщение об ошибке можно закрыть.
- [ ] После временной ошибки приложение можно использовать без перезагрузки, если операция повторена.
- [ ] Необработанные технические детали не показываются пользователю.

## 15. Доступность и клавиатура

- [ ] Страница имеет один основной заголовок первого уровня.
- [ ] Поля форм связаны с видимыми `label`.
- [ ] Accessible name полей не включает счётчики и тексты ошибок.
- [ ] Ошибки связаны с полями через `aria-describedby`.
- [ ] Интерактивные элементы доступны через `Tab`.
- [ ] Порядок фокуса соответствует визуальному порядку.
- [ ] Кнопки активируются клавишами `Enter` и `Space`.
- [ ] Модальные окна удерживают фокус внутри себя.
- [ ] После закрытия модального окна фокус восстанавливается.
- [ ] Декоративные элементы скрыты от accessibility tree.
- [ ] Активные состояния не передаются только цветом.
- [ ] Видимый focus outline присутствует.

## 16. Интерфейс и совместимость

- [ ] Основной сценарий работает в актуальном Chromium.
- [ ] Интерфейс остаётся читаемым при ширине 1440 px.
- [ ] Интерфейс остаётся доступным при уменьшении ширины окна.
- [ ] Горизонтальное переполнение контролируется на узком экране.
- [ ] Текст не перекрывает соседние элементы.
- [ ] Модальные окна не выходят за границы viewport.
- [ ] Масштабирование страницы до 200% не блокирует основные действия.
- [ ] Русский текст отображается без проблем с кодировкой.
- [ ] Даты и время имеют единообразный формат.

## 17. API и данные

- [ ] Успешные операции возвращают ожидаемые HTTP-статусы.
- [ ] Ошибки валидации возвращают структурированный ответ.
- [ ] Отсутствующий ресурс возвращает `404`.
- [ ] Неавторизованный запрос к защищённой операции отклоняется.
- [ ] Недопустимое бизнес-правилом действие отклоняется.
- [ ] Создание записывает данные в базу один раз.
- [ ] Редактирование не изменяет поля, значения которых пользователь не менял.
- [ ] Изменение статуса сохраняется в базе.
- [ ] Удаление удаляет только выбранную запись.
- [ ] Фильтрация, поиск, сортировка и пагинация согласованы между UI и API.
- [ ] В логах есть информация, достаточная для локализации ошибки.
- [ ] Чувствительные данные и пароль не записываются в логи.

## 18. Завершение прогона

- [ ] Все Critical-проверки выполнены.
- [ ] Все High-проверки выполнены.
- [ ] Открытые дефекты зарегистрированы.
- [ ] Для дефектов приложены необходимые доказательства.
- [ ] Блокирующие и критические дефекты отсутствуют.
- [ ] Результат прогона и известные ограничения зафиксированы.
