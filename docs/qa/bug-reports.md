# Баг-репорты Internal Ticket System

Документ содержит дефекты, обнаруженные во время ручного тестирования, разработки автотестов и настройки CI. Все перечисленные дефекты исправлены и прошли ретест.

## Шкала серьёзности

- **Blocker** — тестирование или использование системы невозможно;
- **Critical** — нарушен критический бизнес-сценарий или безопасность данных;
- **Major** — основная функция работает некорректно, но существует обходной путь;
- **Minor** — локальная проблема интерфейса, доступности или удобства без потери данных.

## BUG-001 — Длинный заголовок нарушает разметку таблицы

| Поле | Значение |
|---|---|
| Статус | Fixed |
| Severity | Major |
| Priority | High |
| Компонент | Frontend / таблица заявок |
| Окружение | Chromium, viewport 1440×900, Docker E2E |
| Воспроизводимость | 100% |

### Предусловия

- Приложение запущено.
- Пользователь находится на главной странице.

### Шаги воспроизведения

1. Создать заявку с заголовком длиной 120 символов.
2. Закрыть окно успешно созданной заявки.
3. Найти заявку в таблице.
4. Проверить расположение содержимого строки.

### Фактический результат

Заголовок полностью растягивает ячейку, перекрывает соседние столбцы и нарушает читаемость статуса, приоритета и дат.

### Ожидаемый результат

Длинный заголовок ограничен шириной столбца, визуально сокращён и не влияет на соседние элементы. Полное значение остаётся доступным пользователю.

### Исправление

- Для текста заголовка добавлен отдельный контейнер с ограничением ширины и визуальным сокращением.
- Полное значение доступно через атрибут `title`.
- Поведение приведено к уже существующему сокращению длинного описания.

### Ретест

- Заголовки длиной 3 и 120 символов отображаются без нарушения таблицы.
- Соседние столбцы сохраняют ширину и остаются доступными.
- Граничные значения заголовка проверяются E2E-тестами.

## BUG-002 — Accessible name поля описания включает счётчик и сообщение об ошибке

| Поле | Значение |
|---|---|
| Статус | Fixed |
| Severity | Major |
| Priority | High |
| Компонент | Frontend / формы создания и редактирования |
| Окружение | Chromium, Playwright accessibility tree |
| Воспроизводимость | 100% |

### Предусловия

- Открыта форма создания или редактирования заявки.

### Шаги воспроизведения

1. Найти поле «Описание» через accessibility tree.
2. Ввести текст длиннее 1000 символов.
3. Повторно проверить accessible name поля.
4. Попытаться найти поле точным локатором по label `Описание`.

### Фактический результат

Внешний `<label>` содержит поле, счётчик символов и текст ошибки. Из-за этого accessible name поля изменяется и включает посторонний динамический текст. Точный локатор по имени `Описание` перестаёт находить элемент.

### Ожидаемый результат

Accessible name поля всегда равен `Описание`. Счётчик и сообщение ошибки передаются отдельно и не изменяют название элемента управления.

### Исправление

- Внешний `<label>` заменён контейнером группы поля.
- Отдельный `<label htmlFor="...">` связан только с `textarea`.
- Ошибка связана с полем через `aria-describedby`.
- Невалидное состояние передаётся через `aria-invalid`.

### Ретест

- Поле стабильно находится через `get_by_label("Описание", exact=True)`.
- Accessible name не меняется при вводе текста и появлении ошибки.
- Реактивная валидация создания и редактирования проходит в E2E.

## BUG-003 — Readiness step CI завершается ошибкой при временном connection reset

| Поле | Значение |
|---|---|
| Статус | Fixed |
| Severity | Major |
| Priority | High |
| Компонент | CI / запуск E2E-окружения |
| Окружение | GitHub Actions, Docker Compose |
| Воспроизводимость | Периодическая |

### Предусловия

- В CI запускается новый Docker Compose-проект.
- nginx или backend ещё завершают инициализацию.

### Шаги воспроизведения

1. Запустить E2E job в чистом CI-окружении.
2. Сразу после запуска контейнеров выполнить readiness-запрос к `/health`.
3. Наблюдать результат `curl` во время старта сервисов.

### Фактический результат

При временном сбросе соединения `curl` завершается с кодом 56. Опция повторения только для отказа соединения не обрабатывает этот тип ошибки, поэтому E2E job падает до запуска тестов, хотя приложение становится доступно через несколько секунд.

### Ожидаемый результат

Readiness step повторяет запрос при временных сетевых ошибках в пределах заданного таймаута и завершается успешно после готовности приложения.

### Диагностические данные

```text
curl: (56) Recv failure: Connection reset by peer
Process completed with exit code 56
```

### Исправление

- Для `curl` включён повтор при всех временных ошибках.
- Добавлены ограничения времени соединения и запроса.
- При окончательном падении CI публикует Docker logs.

### Ретест

- Повторный CI-запуск успешно дождался `/health`.
- API, frontend и E2E jobs завершились успешно.
- Диагностические артефакты продолжают публиковаться при падениях.

## BUG-004 — Pytest не собирает API- и E2E-тесты с одинаковыми именами модулей

| Поле | Значение |
|---|---|
| Статус | Fixed |
| Severity | Major |
| Priority | High |
| Компонент | Test infrastructure / pytest collection |
| Окружение | Windows, Python 3.12, pytest |
| Воспроизводимость | 100% |

### Предусловия

- В каталогах `tests` и `e2e/tests` существуют файлы `test_auth.py`.
- Оба набора запускаются одной командой pytest.

### Шаги воспроизведения

1. Открыть корень проекта.
2. Запустить сбор всех тестов.
3. Проверить этап pytest collection.

### Фактический результат

Pytest импортирует один файл как модуль `test_auth`, затем обнаруживает второй модуль с тем же именем и завершает collection ошибкой `import file mismatch`.

### Ожидаемый результат

API- и E2E-тесты имеют уникальные полные имена модулей и успешно собираются в одном процессе.

### Диагностические данные

```text
import file mismatch:
imported module 'test_auth' has a different __file__ attribute
```

### Исправление

- Каталоги `tests` и `e2e/tests` оформлены как отдельные Python packages с помощью `__init__.py`.
- Полные имена модулей стали различаться: `tests.test_auth` и `e2e.tests.test_auth`.

### Ретест

- Collection обоих наборов завершается успешно.
- API- и E2E-тесты запускаются отдельно и совместно без конфликта имён.

## BUG-005 — Название и описание быстрого фильтра объединены в одно accessible name

| Поле | Значение |
|---|---|
| Статус | Fixed |
| Severity | Minor |
| Priority | Medium |
| Компонент | Frontend / быстрые фильтры |
| Окружение | Chromium, Playwright accessibility tree |
| Воспроизводимость | 100% |

### Предусловия

- Открыта главная страница с блоком быстрых фильтров.

### Шаги воспроизведения

1. Найти группу «Быстрые фильтры» через accessibility tree.
2. Проверить accessible name кнопки «Закрытые».
3. Попытаться найти кнопку по точному пользовательскому названию.

### Фактический результат

Тексты `<strong>Закрытые</strong>` и `<span>Только Done</span>` участвуют в вычислении одного accessible name. Название зависит от объединения двух визуальных строк и не отделяет основное действие от пояснения.

### Ожидаемый результат

Accessible name кнопки равен `Закрытые`, а текст `Только Done` доступен как отдельное описание.

### Исправление

- Блок кнопок оформлен как именованная группа «Быстрые фильтры».
- Основной текст кнопки связан через `aria-labelledby`.
- Поясняющий текст связан через `aria-describedby`.
- E2E-локаторы используют точное имя кнопки без регулярных выражений.

### Ретест

- Кнопка находится через `get_by_role("button", name="Закрытые", exact=True)`.
- Accessible name и description разделены.
- Параметризованные E2E-тесты быстрых фильтров проходят для всех статусов.
